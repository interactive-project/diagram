# Portable diagram v1

DiagramConfig separates graph (nodes, edges, groups) from optional view (node positions and layout hints). Coordinates never enter the headless state or actions. Layout hints identify a host-selected implementation; they do not invoke one. Rendering, automatic layout and host coordinate interactions belong to later issues.

All node, edge, port and group IDs are globally unique case-sensitive ASCII local identifiers, stable across updates. IDs cannot be changed by update. A deleted ID can be reused only as a new entity; this initial domain has no collaborative identity/tombstone or undo history. Nodes have kind, scalar typed attributes, ordered ports and nullable groupId. Groups have nullable parentId and scalar attributes. Optional labels everywhere use ContentNode. Edges have ordered source/target endpoints, nullable port IDs, directed boolean and attributes. Null port means connecting the node itself. Parallel edges and self-loops are permitted; array declaration order is retained.

For a directed connection source ports must output or be bidirectional, target ports input or bidirectional. For undirected connections all selected ports must be bidirectional; source/target are declaration endpoints only, with no directional semantics. Two selected ports must have exactly matching dataType identifiers; no coercion or wildcard inference. A connection with only one selected port has no inferred type for the bare-node endpoint. Physical laws, circuit evaluation, port cardinality and domain-specific type subtyping are not claimed.

Bounds: 512 nodes, 1000 edges, 128 groups, 16 ports per node, 32 scalar attributes per entity; finite JSON numeric values only. Graph JSON is bounded at 2 MiB / depth32 / 50000 nodes / 1000 per collection / 100000 per string; validation also checks ContentNode semantics offline. Core action payload budgets (including 4000-character strings) apply before domain admission. Safe diagnostic codes/pointers do not echo labels or attributes.

createDiagramPorts returns actual Core StatePorts. State v1 contains deletionPolicy and semantic graph only. Diagram add/update/remove/connect actions use entity node/edge/group plus value/id/changes as applicable; connect adds an edge. Updates replace individual fields (including complete attributes/ports arrays), never merge nested attributes or rename IDs. Batch accepts 1..64 operations. A fresh working graph receives all operations, then schema/content/semantic validation runs once; only a valid final graph commits. No intermediate events/state, and any failure leaves the old state and revision untouched. Batches may temporarily dangle connections if repaired before final validation.

Default deletionPolicy reject allows deletion only when the final graph has no dangling membership or endpoints. Cascade removes incident edges when deleting a node. Deleting a group recursively removes descendant groups, member nodes and incident edges, retaining unrelated nodes/groups. Port removal through a node update does not silently cascade: update/remove affected edges explicitly in the same batch. Group cycles, duplicate IDs, unknown groups/ports/nodes, direction and type conflicts reject the complete transaction. Repeating add/remove under a new action ID rejects when its precondition fails; repeated update with the same values is accepted as a fresh transaction. Protocol action identity/sequence enforcement remains Core-owned.

Evaluation is explicitly unevaluable/unassessed. Core emits its standard interaction/lifecycle events; domain-specific event enrichment, diagram evaluation, snapshots, renderers and layout adapters remain separate gates. Shared Protocol and ContentNode schemas are unchanged; optional domain-owned schema and headless StatePorts are recorded in improvement-proposals/decisions/diagram-model-v1.md.
